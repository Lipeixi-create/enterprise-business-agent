## 3. 架构与功能边界

- 单个 LangGraph 图：`decide → act → decide`；模型只提出工具调用，不直接执行 SQL。
- 工具全部只读；权限与参数在代码层校验，模型无法绕过。
- 业务查询经过语义层、SQL Guard 和只读执行器；超时、行数上限、offset 上限均强制执行。
- 人工审批只控制报告发布状态，不授予业务库写权限。
- 未引入 Kafka、Kubernetes、微服务或额外 Agent。

## 4. 安全

| 控制 | 状态 |
| --- | --- |
| API Key + 角色认证 | 已实现；`EBA_ALLOW_ANONYMOUS_API` 生产必须为 false |
| 角色域/指标限制 | 已实现；默认策略见 `security/auth.py` |
| 数据库只读角色 | 已实现；Preflight 检查 superuser/DDL/写权限 |

| 审批隔离 | `approval:read` 仅本人，`approval:read_any` 才可跨用户 |

未做：真实渗透测试、生产网络边界验证、密钥轮换演练。

## 5. 可靠性与数据一致性

- Checkpoint：按 `thread_id` 恢复；恢复失败显式记录，不伪装成功。
- 生命周期预算：单次执行、累计生命周期、token、工具调用、连续失败均有上限。
- Claim/Lease/Fencing：数据库条件更新，失去租约返回 409 `run_claim_conflict`。
- 模型异常：截断、空响应、格式错误、超时、连接/认证失败、非法工具名/参数均有确定性与脚本化测试。
- 叙述截断：分段生成 + 逐段校验 + 确定性回退，失败在报告中标注。
- Evidence/Finding/Report：引用 ID 必须存在于 ledger；Numeric Validator 记录问题与未验证数字。
- 审批：报告版本指纹与审批绑定，决策幂等。

## 6. 评测与可观测性

评测：

- 92 条语料（基础 26 + Phase 7 66），覆盖五业务域、跨域、异常归因、指标歧义、缺数、零分母、越权、提示注入、预测和多步调查。
- 期望值由同一确定性数据库上的 canonical 查询生成。
- 多维评分：工具选择、参数、查询、任务完成、证据引用、Finding 引用、Numeric Validator、报告结构、数字准确、安全拦截、错误拒绝、叙述完整。
- 回归门禁：普通 `pytest` 默认排除 `live_model`；真实模型评测必须显式 `--allow-live-model`。

可观测性：

- `/api/v1/metrics` 提供运行质量、工具、模型、成本、性能、分域、校验、审批、数据库和 tracing 状态。
- 成本仅在配置单价时估算，并标注价格来源与"非账单"。
- OTel span 覆盖 Run、决策、模型、工具、DB、Checkpoint，携带 `run_id`/`tool_call_id`。
- 无真实 OTLP 后端，外部链路未验证。

## 8. 已知未验证项与残留风险

1. **真实模型未在本轮重跑**：Phase 6 五场景的 GLM 数据来自上一轮记录；Key 状态未人工确认。
2. **真实 OTLP 后端未验证**：只能确认 span 生成与计数，不能确认后端收到。
3. **生产环境未接触**：所有 PostgreSQL 验证均在本地临时容器/测试库完成。
4. **未做容量压测**：并发上限、连接池、长查询堆积未量化。
5. **未做多机灾备**：运行时库与业务库可能同实例，故障域未隔离。
6. **清理任务依赖进程生命周期**：需要独立定时任务时应在部署层补充。
7. **工具重试次数未持久化**：可观测性字段为 `null`。
8. **评测语料绑定当前数据集**：数据或语义层变更后需重建并重新验证。
9. **模型叙述回退**：失败时使用确定性文本并标注警告，可读性下降但不影响结构化结果。

## 9. Go / No-Go 建议

**Go（进入预发布）条件：**

- 第 7 节 1–5 项完成。
- 预发布环境 `preflight` 零 FAIL。
- 全量测试与 PostgreSQL 集成测试通过。
- 至少完成一轮真实模型评测，失败用例有归因。

**No-Go（禁止生产切流）条件：**

- 任一 `preflight` FAIL。
- 运行时角色具备 DDL 或业务表写权限。
- 未验证备份恢复。
- 真实模型评测未执行或存在未归因的高风险失败（越权、编造数字、证据缺失）。
- 未确认密钥轮换与最小权限 API Key。

**回滚原则：**

- 保留旧实例与只读副本；切换前确认运行时库可回滚到上一版本结构。
- 不以删除运行时数据作为回滚手段；Run/Evidence/Report/审批记录必须保留。
- 任何回滚与数据修复都需人工变更单。
